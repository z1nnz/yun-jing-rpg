## 1. 硬規則（任何人、任何工作都不能違反）

1. **一個世界**：所有區域共用世界常數（建模規格 §11.1）。區域可以換色、換材料、換植被，不能換光照邏輯、比例和筆觸。
2. **1 單位 = 1 m，角色 1.75 m。** 所有尺寸從這裡算。
3. **伺服器說了算**：背包、修為、採集、機緣、種植，都由伺服器結算。用戶端只負責顯示，不自己加東西。
4. **品質優先，也要跑得動**：不要求面數下降；效能用 LOD、分段載入與手機實測處理，不用犧牲外觀。
5. **不能花錢變強**：付費只賣外觀。任何設計不能讓付費影響資質、修為、機緣。
6. **機緣永不標在地圖上**，也不能用 UI 箭頭指路。
7. **沒有真正的壞人**：任何角色、宗門的文字都不能寫成單純的邪惡（世界觀總綱 §四）。
8. **交件不提交**：協作者與 Codex 交到自己的工作樹；整合者審過後，以 z1nnz 名義提交。
9. **用語一致**：照第 3 節的用語表；玩家看得到的文字不出現「洞府」（入宗後叫「住處」）。

## 2. 世界與關卡設計規範（新增）

### 2.1 空間分三種，每一種東西只放在一種空間

| 空間 | 誰的 | 放什麼 | 不放什麼 |
|---|---|---|---|
| **領地**（新手自己的家；入宗後是宗門分派的住處） | 個人，別人進不來 | 種植、練功練氣、閉關、煉丹、收藏、佈置 | 採集點、靈獸、機緣 |
| **大世界**（新手大世界、之後的州域） | 共用、連線 | 探索、採集、狩獵、見聞、機緣、世界事件、主線、交易 | 需要長時間待著的個人活動 |
| **秘境與宗門** | 秘境：組隊；宗門：同門共用 | 秘境挑戰、宗門任務、師承 | — |

### 2.2 一個區塊的組成

- 每個區塊 **100 × 100 m**，跑過一塊約 25 秒（區塊規劃 §3）。
- 每塊至少要有：
  - 一個**值得停下來的東西**（地標或機緣）；每個區域至少一個從 150 m 外看得出輪廓的大地標；
  - 一條**主路**、兩條以上**小徑**；
  - 兩處以上**採集點**（村核心可以少）；
  - 一個以上**見聞**；
  - 零到一個**機緣**（伺服器決定誰遇得到）；
  - 每兩三塊一處**休息點**（亭、樹下、橋）。
- **視線引導**：站在區塊入口，至少看得到一個地標和一條路。玩家不用地圖也知道往哪走。
- **節奏**：開闊（看景）→ 狹窄（林間、巷道）→ 開闊（到達）。同一種地形不要連續超過一塊（100 m）。
- **邊界**：外緣是雲海斷崖或高山（世界觀 §二），不用看得見的牆。空氣牆只放在斷崖上，而且要有斷崖。

### 2.3 道路與尺度（細節見區塊規劃 §2）

| 項目 | 標準 |
|---|---|
| 主路寬 | 3.0–3.4 m；支路 2.4–2.6 m；小徑 2.0–2.2 m |
| 建築間距 | 至少 3 m |
| 坡度 | 沿路 < 20°；角色上限 35°，更陡視為牆 |
| 跨區 | 兩區之間 30–60 m 過渡帶（建模規格 §11.3） |
| 見聞微光 | 14 m 內才出現 |
| 尺寸等級 | 格位只從 XS–XXL 六級挑（區塊規劃 §2.2） |
| 格位 | 所有建築與大型道具一律用格位放進遊戲（區塊規劃 §5 格位合約） |

### 2.4 見聞與機緣怎麼藏

- **見聞**：大家都找得到，給世界觀的一小片。藏在「多看一眼」的地方：屋後、樹根、橋下。
- **機緣**：只有部分玩家遇得到。由伺服器依機率、時辰天氣、資質與經歷、全服限量決定。
- 每一則文字都要對應世界觀總綱裡的一層（總綱 §六），寫進 `packages/content/fortunes.json` 時標明指向哪一層。

## 3. 文字與用語規範（新增）

### 3.1 語氣

- 繁體中文。白話為主，帶一點古意；不用網路用語。
- 句子短。介面文字一行不超過 16 字；見聞內文不超過 60 字。
- 不說破：見聞和對話只說「看到什麼」，不說「這代表什麼」。

### 3.2 用語表

| 用這個 | 不要用 | 說明 |
|---|---|---|
| 領地 | 家園、莊園 | 新手自己的地；入宗前 |
| 住處 | 洞府 | 入宗後宗門分派的個人空間 |
| 大世界 | 野外、地圖 | 共用的連線世界 |
| 見聞 | 彩蛋、收集品 | 人人找得到的發現 |
| 機緣 | 隨機事件 | 只有部分人遇得到 |
| 靈脈、脈息 | 能量、魔力 | 世界觀核心 |
| 修為、境界 | 等級、經驗值 | |
| 乾坤袋 | 背包 | 介面名稱 |
| 旅途手札 | 任務日誌 | 記錄見聞、主線 |

### 3.3 取名三層法

所有新的地名、宗門、物品、靈獸、角色，都照 [世界觀總綱 §二之三](../story/world-lore-v1.md)：
- 表面好聽；
- 藏一個典故（中國、日本、希臘、北歐、埃及、印度……）；
- 典故暗示主線的一部分。

交件時在旁邊寫一行「典故：…；伏筆：…」。

### 3.4 不交代原則

任何文字都不能說出未來會發生什麼，也不能直接解釋世界的真相（世界觀總綱 §二之二）。

### 3.5 資料放哪裡

- 所有玩家看得到的文字放 `packages/content/*.json`，不寫死在程式裡（暫時寫死的要在程式旁註明，並列入待辦）。

## 5. 程式規範（新增，給寫程式的協作者）

- **伺服器動作**：
  - 每個會改變玩家資料的動作都是 `services/api/src/game.ts` 裡的一個 `case`；
  - 帶 `requestId`，重送不重複結算；
  - 內容由 `packages/content` 驗證；
  - 每個新動作都要有 `services/api/tests/*.test.ts`。
- **Unity 用戶端**：
  - 場景由產生器（`QingxiNoviceVillageBuilder`、`QingxiBlockBuilder`）從資料生成，不手動擺；
  - 新玩法加進 `QingxiAbcSmoke` 的自動檢查。
- **離線可玩**：連不上伺服器時保留本機紀錄，連上後補送。
- **測試全綠才交**：
  - 伺服器測試；
  - 配置測試：`node --test tools/qingxi-terrain/novice-village.test.mjs`；
  - 遊戲煙霧測試：`--abc-smoke`。

## 6. 交件與驗收（每一件都一樣）

交件要附：
1. **成品**：放在自己的工作樹，路徑寫清楚。
2. **截圖**：
   - 模型：四視圖加一張遊戲內截圖（建模規格 §8）；
   - 介面：手機直向、橫向和電腦各一張；
   - 關卡：入口視角、地標視角、俯視各一張。
3. **數字**：面數、貼圖尺寸、檔案大小、幀數（有的話）。
4. **自我檢查**：照下表打勾，沒達到的寫原因。
5. **未完成清單**：還差什麼、為什麼。

| 檢查 | 模型 | 介面 | 關卡 | 程式 |
|---|:-:|:-:|:-:|:-:|
| 符合世界常數（同一個世界） | ✓ | ✓ | ✓ | |
| 尺寸以 1.75 m 人形尺驗過 | ✓ | | ✓ | |
| 有 LOD1／LOD2（品質優先，不要求減 LOD0） | ✓ | | ✓ | |
| 手機網頁可用 | ✓ | ✓ | ✓ | ✓ |
| 用語照第 3 節 | | ✓ | ✓ | ✓ |
| 測試全綠 | | | ✓ | ✓ |
| 沒有提交、沒有推送 | ✓ | ✓ | ✓ | ✓ |

整合者驗收後：
- 通過：放進遊戲、提交，在工作包標 ✅；
- 部分通過：寫在審查文件（例如 `codex-v2/review-*.md`），列出要改的地方。

## 7. 怎麼改規範

- 任何人發現規範不合理，寫進交件回報的「建議」一節。
- 整合者決定後更新對應文件，並在文件開頭寫日期與改了什麼。
- 世界常數和第 1 節的硬規則只有 z1nnz 能改。
