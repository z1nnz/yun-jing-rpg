> 2026-10-29，z1nnz 指示、Claude Code 撰寫。
> z1nnz 的要求：「先規劃好，再做比例的劃分和要建多大；新手大世界一個區塊一個區塊做；每個區塊裡建築、物件、模型放在哪裡、誰負責，要先釐清，再去規劃物件大小。規劃出來之後就可以理所當然地放進遊戲裡。」

## 0. 一句話

**先定位置和大小，再做模型。** 每一件建築、道具、NPC 在做之前，就先在地圖上有一個「格位」：位置、朝向、長寬高上限、負責人。建模者照格位的尺寸做，交件後遊戲自動把它放進格位。還沒做的格位，在遊戲裡先顯示成半透明的標示盒，走得到、看得到。

## 1. 規劃順序（由大到小，不能跳）

| 層 | 是什麼 | 尺度 | 資料在哪裡 |
|---|---|---|---|
| ① 世界 | 整個新手大世界 | 約 800 × 600 m | `tools/qingxi-terrain/novice-world-blocks.json` |
| ② 區域 | 四區：A 青溪河谷、D 古林、B 垂直山城、C 裂靈湖 | 數百公尺 | 同上 `regions` |
| ③ 區塊 | 世界切成 **100 × 100 m** 的格子，一次做一塊 | 100 × 100 m | 同上 `blocks` |
| ④ 分區（平台） | 區塊裡的平地：廣場、民居區、鐵匠區…… | 10–25 m | 區塊的 layout JSON，`pads` |
| ⑤ 格位 | 一件建築或道具的位置、朝向、尺寸上限、負責人 | 0.5–10 m | 區塊的 layout JSON，`placements` |
| ⑥ 模型 | 照格位尺寸做出來的成品 | — | `apps/game/Assets/...` |

**改上層就要重新檢查下層**：例如移動一個分區，裡面的格位要跟著移，再跑一次測試。

## 5. 格位合約（給每一位建模者）

接到一個格位，就照這張表做：

1. **尺寸**：
   - 模型的長、寬、高都不能超過格位的 `footprint`（w × d × h）。
   - w 是模型自己的 X 方向，d 是 Z 方向（Unity 座標，旋轉前）。
   - 超過 10% 時，生成器會記錄 `QINGXI_FOOTPRINT` 警告。
2. **正面**：模型的正面朝 Unity 的 **+Z**（等於 Blender 的 **−Y**）。格位的「朝向」由生成器旋轉，模型本身不要先轉。
3. **原點**：底部中心，底部高度 0（接地規格）。生成器會把模型的底部放在平台高度上。
4. **匯出**：FBX 設定照建模規格；旋轉 0、縮放 1。
5. **放哪裡**：
   - FBX 放 `apps/game/Assets/YunJing/Models/<套件>/`；
   - 然後在 `novice-village.json` 把該格位的 `model` 填上路徑、`status` 改成 `ready`；
   - 不會改 JSON 的人，交件時告訴核心組，由核心組改。
6. **重新生成**後，模型就出現在格位上，原本的半透明盒子消失。

## 6. 怎麼修改計畫

1. 改 `tools/qingxi-terrain/novice-village.json`（分區、道路、格位）。
2. 跑測試：`node --test tools/qingxi-terrain/novice-village.test.mjs`，共 11 項，會檢查：
   - 格位不重疊；
   - 格位不壓路，也不超出分區；
   - 溪流不切到分區、道路、靈草；
   - 坡度不超過 20°；
   - 每個格位都有負責人、狀態、尺寸。
3. 重畫地圖：`node tools/qingxi-terrain/render-plan.mjs`，輸出 `docs/execution/maps/*.svg`。
4. 重新生成場景：`./tools/unity.ps1 -Target NoviceVillage`。生成記錄裡的 `QINGXI_SLOTS` 會寫出幾個格位還在等模型、幾個模型超出格位。
