# 草稿｜協作者模型的接地規格

> **狀態：草稿，待 z1nnz 同意後才併入工作包。** 起因是 2026-10-29 討論：協作者交的道路網格、草皮片、地形磚放到起伏地面上會互相穿插。青溪改為「地形＋路線資料＋散布」之後，模型交付需要配合下列規格。與 `CLAUDE_CODE_WORKFLOW.md` 第 2、3 節一起看；這份只補「怎麼接到地形上」。

## 1. 先分清楚你做的是哪一類

| 類別 | 例子 | 誰負責地面 |
|---|---|---|
| 擺放件 | 丹爐、告示牌、掩體、房屋、樹、大石 | 地形；模型只要底部正確 |
| 結構件 | 橋、石階、台基、石板路段、路口件、水渠、棧道 | 模型本身；地形塑形去接它 |
| 散布件 | 單叢草、花、蘆葦、小石、落葉 | 引擎依規則大量擺放 |
| 地面 | 泥土路面、草地、河岸坡、地形起伏 | **不交模型**，核心組用地形與路線資料處理 |

不確定時，在 README 寫出你認為的類別，並附玩家視角截圖。

## 2. 原點與接地

- 1 單位＝1 m，Y 向上（Blender Z 向上，匯出時轉換）。原點在**腳印中心、底部高度 0**。
- 擺放件**不附地面底板**：不要在模型下面墊一塊草皮或土塊來「站穩」。地形會給它地面。
- 需要埋進土裡的部分（樹根、石頭下半、木樁）可以低於 0，但在 README 寫明「設計埋入深度」，例如「埋 0.15 m」。
- 散布件可以帶**根部的小土堆**（直徑不超過本件寬度），幫助和地面融合；不能是一整片地皮。

## 3. 結構件的接口

- 每個會接路或接地形的端面，在 README 的接口表寫：寬度、端面中心座標、端面高度、朝向。例如「北端：寬 2.6 m、中心 (0, 0, 6)、高 0、朝 +Z」。
- 兩端高度不同的件（石階、坡道）寫出每階高度與總高差；每一步不超過 0.3 m，坡度不超過 20°（角色可走上限是 35°，但 20° 以下才自然）。
- 路口件的每個接口規格與直段完全相同，支路只接到路口件為止，不互相插入。
- 橋、棧道另交**簡化碰撞網格**（命名 `*_COL`），走起來是平的，不要用欄杆縫隙或木板間隙當碰撞。

## 4. 碰撞與 LOD

- 碰撞以簡單形狀為主：盒、膠囊、少面數凸包；在 `model_info.json` 的 `collision` 欄寫明（B 的丹房件已有好例子）。
- 擺放件的碰撞底部和視覺底部同高，避免角色腳下懸空或卡進去。
- 散布件不加碰撞，並提供至少一層 LOD 或更少面數的遠景版本。

## 5. 交付前自己檢查

- 在 Blender 裡把模型放在一塊**傾斜 10° 的平面**上看一次：擺放件底部要能貼住，不會一邊懸空太多；如果會，就考慮把底部做得窄一點或加埋入深度。
- 跑 `node tools/qingxi-terrain/asset-inventory.mjs`，確認你的件分類正確、底部高度符合設計。
- 核心組接進場景後會跑 `tools/qingxi-terrain/check-grounding.ps1`；懸空、路上長草、路面疊面都會被列出。

## 不在這份規格內

- 地形本身的起伏、道路走向與草的分布由核心組負責，協作者不需要做。
- 已交付的舊件不要求重做；需要調整的列在 `docs/execution/qingxi-terrain-asset-inventory.md`，由核心組在擺放時補償，或與原作者另外約定。
