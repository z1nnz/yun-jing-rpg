# 整合、驗證與第一次試玩

適用範圍：核心組、協助者 A、協助者 B  
目標：證明「青溪山兔採獵—回村出售」真的可玩、資料不重複、素材可重建，而不是只看檔案是否存在。

## 整合順序

1. 核心組先合併內容、契約、服務端結算與測試。
2. 協助者 A 的山兔資產通過 Blender／FBX 驗證後合併。
3. 協助者 B 的灰盒 Builder 通過檔案檢查後合併。
4. 從最新 main 建立 integration/qingxi-hunt-slice。
5. 在整合分支設定 Prefab、Animator、碰撞、出生點、NavMesh、商販互動和客戶端顯示。
6. 通過自動測試、Unity 編譯、兩端試玩後才合回 main。
7. 任一部分失敗時回到原 PR 修復，不在整合分支偷偷改掉來源問題。

## 提交前檢查

### 所有人

- 先同步最新 main，再執行自己的測試。
- git status 只出現本次任務檔案。
- 不含憑證、.env、Library、Temp、Logs、建置輸出或個人絕對路徑。
- PR 寫出「做了什麼、怎麼驗證、尚未驗證什麼」。
- 二進位素材使用 Git LFS；來源、作者與授權狀態寫清楚。

### 程式與內容

執行：

    npm ci
    npm run typecheck
    npm test
    npm audit --omit=dev --audit-level=high

全部成功才可進入整合。若新增 hunting.json，需有內容結構測試，缺欄位、負值、總機率錯誤時應阻止啟動或測試失敗。

### Blender 資產

- 母稿可重新開啟。
- FBX／GLB 可回匯。
- 尺寸誤差小於 1 mm。
- 五個動畫存在，循環／非循環設定有紀錄。
- LOD、材質槽、骨數、三角面有數據。
- 至少正、側、後和 Idle、Flee、Death 預覽。
- 幾何有改版時，必須有先於建模保存的 AI 三視圖。

### Unity

只有實際通過才勾選：

- Unity 6000.0.85f1 能開啟專案並完成套件解析。
- C# Console 無編譯錯誤。
- QingxiHuntGraybox Builder 能由空白 Generated 目錄重建場景。
- 山兔 FBX 尺寸正確，五個 clip 可播放。
- NavMesh 烘焙成功；玩家與兔子可走指定路線。
- Windows Client 能連 Linux Dedicated Server。
- 斷線重連後，背包與獎勵和 API 一致。
- Android 真機測試完成前，不標記手機效能通過。

Unity 授權尚未完成時，本輪只能通過「程式碼／資料／Blender 靜態驗證」，不能寫可運行或可試玩。

## 第一次內部試玩腳本

試玩長度約 25–35 分鐘，這是測試流程，不是要求正式玩家每天在線的時長。

### 測試角色

- 角色 1：常資，主測移動、攻擊、狩獵與出售。
- 角色 2：凡骨，主測基礎武技、採集替代路線與共同狩獵。
- 同時準備一個重連客戶端，用於網路中斷驗證。

### 流程

1. 兩人從聚落出口出生，確認彼此可見且碰撞不重疊。
2. 不看開發者地圖，由環境線索尋找採藥林。
3. 一人採集，另一人循腳印找第一組山兔。
4. 刻意追丟一隻兔子，觀察能否重新判斷方向。
5. 刻意打空一次，確認不會產生掉落。
6. 兩人同時攻擊同一隻山兔，確認死亡只發生一次。
7. 在死亡結算時中斷其中一個客戶端，再登入檢查收據和背包。
8. 重送同一 deathId，確認物品沒有增加。
9. 保留一件材料、出售另一件；重送出售 requestId。
10. 使用回程捷徑返回出口，記錄從獵物死亡到商販的時間。
11. 角色 2 不狩獵，只採藥與返回，確認仍有合理活動。
12. 連續遊玩 30 分鐘，觀察記憶體、幀時、動畫、導航與連線錯誤。

## 測試矩陣

| 案例 | 預期 |
|---|---|
| 普通擊殺 | 一次死亡、一次獎勵、背包正確 |
| 攻擊落空 | 無死亡、無獎勵 |
| 兩人同時最後一擊 | 伺服器只確認一個 deathId |
| 相同 deathId 重送 | 回傳原收據，物品不增加 |
| 結算途中斷線 | 重登後不是零份或兩份，而是唯一正確結果 |
| 重複出售 | 只扣物品及加靈石一次 |
| 客戶端改掉落數量 | 服務端拒絕或忽略 |
| 兔子逃跑 | 沿可導航路徑，不穿牆、不進深水 |
| 玩家卡在岩石 | 能自行離開或回安全點 |
| 凡骨角色 | 可用基礎武技與採集取得成果 |
| 無山兔可獵 | 有採藥替代，不阻止玩家自由活動 |
| 區域重啟 | 已確認物品保留，未確認敵人狀態安全重建 |

## 試玩記錄表

每位測試者記錄：

- 找到第一個線索所需時間。
- 找到第一隻山兔所需時間。
- 首次有效命中與首次擊殺所需時間。
- 追丟後能否重新找到。
- 從擊殺到回村出售所需時間。
- 是否理解材料可保留或出售。
- 哪一刻覺得迷路、被強迫或在純等待。
- FPS、95 百分位幀時、記憶體、斷線次數。
- 遇到的錯誤與重現步驟。

## 嚴重度與放行標準

| 等級 | 定義 | 處理 |
|---|---|---|
| S0 | 複製物品、資料毀損、憑證外洩 | 立即停止整合 |
| S1 | 無法登入、無法完成狩獵、頻繁崩潰 | 修復後重測 |
| S2 | 導航卡死、動畫嚴重破面、主要提示失效 | 本輪修復 |
| S3 | 輕微穿模、文字、非阻斷視覺問題 | 建 Issue 排期 |

放行條件：

- S0、S1、S2 為零。
- 所有 Node 測試通過。
- Unity 編譯與雙端測試有實際紀錄；若授權阻擋，就停在不可玩狀態，不假裝放行。
- 五名不看開發地圖的測試者中，至少四名能在 10 分鐘內自行發現山兔或採集替代路線。
- 沒有人因同一事件收到兩份獎勵。
- 玩法沒有強迫固定在線時長或每日連續登入。

## 測試後決策

依數據只調整造成問題的環節：

- 找不到線索：加強地形、聲音或足跡，不直接加強制箭頭。
- 追逐過長：調整逃跑點距離、掩體與兔子恢復，不提高掉落率掩蓋問題。
- 收益過高：調整市場價格、重生或材料用途。
- 凡骨無法參與：改善基礎武技與環境路線，不取消出生差異。
- 效能不足：先降低同屏兔數、陰影、植物密度、材質與骨骼負載，再重新量測。
