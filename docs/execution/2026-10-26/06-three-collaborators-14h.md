# 三位協作者下一輪執行單（每人約 14 小時）

本輪目標是把青溪現有場景往可觀看、可走通的樣片推進。三人各自使用分支，**不要同時改同一個 `.blend`、Unity 場景或 `tools/art/orient_elder_tree_v10.py`**。先讀 [目前狀態](../../status.md) 與 [工作範圍](../../work-ownership.md)。每項交付需有來源、可重建檔、實際預覽和未完成清單；目前以 PWA／Blender 圖片驗證，不要求在此輪宣稱 Unity 可運行。

## 協作者 A：山兔的可用資產（14 小時）

接續 [既有山兔執行單](02-collaborator-a-rabbit.md)，從 `art/incoming/dondon/QMountainRabbit/v002/` 讀取原件，**不能覆寫原件**。若只做綁骨、動畫、LOD 和碰撞代理，可沿用原模型；若修改兔子外形，先生成、檢視並保存三視圖。

| 時間 | 交付 |
|---:|---|
| 0–2 小時 | 盤點 19 個網格與 22,192 三角面、確認腳掌落地、材質和模型方向；記錄問題。 |
| 2–6 小時 | 在 `art/source/qingxi-mountain-rabbit-v003/` 做骨架與權重，交 idle、hop、flee。 |
| 6–9 小時 | 完成 hit、death；逐段檢查耳、腿、腹部是否穿插或撕裂。 |
| 9–11 小時 | 製作 LOD1、LOD2 和簡化碰撞代理，明列各級面數。 |
| 11–14 小時 | 輸出 FBX／GLB、六向或動作預覽、Blender QA 報告及 README；獨立分支上傳。 |

驗收：五組動畫可循環或播放完畢，原點及比例不跳動，原稿可重新匯出，交付路徑只限 `art/source/qingxi-mountain-rabbit-v003/`、`art/exports/qingxi-mountain-rabbit-v003/` 和相應預覽。不得改掉落 API、宗門或場景。

## 協作者 B：不規則道路與河岸模組（14 小時）

以 [道路三視圖](../../../art/references/qingxi-winding-road-v1/three-view.png) 和五張世界方向圖為視覺目標，參考已有 `art/source/qingxi-world-flora-water-v8.blend`、`art/source/qingxi-detail-props-v2.blend`。目前 v9 已有蘆葦、花叢、苔石和路燈的初版，**不要再做同名四件**。本輪做道路邊界、地面材質和石階銜接，使用獨立原稿 `art/source/qingxi-road-bank-v2.blend`，不編輯 v8／v9／v10 主場景。

| 時間 | 交付 |
|---:|---|
| 0–2 小時 | 標註三視圖中的彎曲半徑、路寬、草土過渡、石塊大小；先出白模走線。 |
| 2–6 小時 | 做三段可拼接不規則土路：直段、左彎、右彎；接縫高度和行走淨寬一致。 |
| 6–9 小時 | 做路緣過渡、碎石、壓實土和局部裸岩；材質重複時仍有自然變化。 |
| 9–11 小時 | 做道路接木橋與河岸石階的兩個收邊件；檢查玩家可走表面。 |
| 11–14 小時 | 輸出 GLB、頂／側／斜視預覽、尺寸及面數報告，提供主場景擺位建議。 |

若新增獨立幾何外形，按 AGENTS.md 先生成並保存該物件三視圖。驗收：三段接縫不露底、路線不呈長直矩形、與 [現有河岸預覽](../../../art/previews/qingxi-world-v9/river-road-details.png) 比較能看見進步。不得動樹伴樹、主場景或協作者 A 的兔子。

## 協作者 C：PWA 行走與鏡頭驗證（14 小時）

在現有 `tools/world-preview/` 建立**獨立**互動樣片，不改 `apps/inspector` 的登入或 API。目的在手機瀏覽器核對世界比例、移動動線和鏡頭遮擋；這不代表 Unity 第三人稱戰鬥已完成。

| 時間 | 交付 |
|---:|---|
| 0–2 小時 | 對齊現有青溪灰盒坐標、村口／橋／採藥林／河岸四個路標。 |
| 2–5 小時 | 滑鼠鍵盤和觸控移動、角色位置顯示、不能越過河和山壁的基本碰撞。 |
| 5–8 小時 | 第三人稱跟隨鏡頭、可調距離與轉向、靠牆時避免視線被遮；保留可讀地標。 |
| 8–11 小時 | 以已有模型或簡化代理標記橋、樹、客舍、淺灘；呈現主要路線與短捷徑。 |
| 11–14 小時 | 桌機與 390px 手機瀏覽器手動試走；記錄卡點、截圖、操作說明和限制。 |

不得聲稱即時多人、實際戰鬥、手機原生效能已驗證。若借用 `art/incoming/dondon` 模型，記錄來源及授權；不要把整包複製到 PWA。此分支只修改 `tools/world-preview/` 和其獨立測試／文件。

## 上傳與整合

三人各建一個 `feature/` 分支，提交前執行自己變更所需測試，附預覽與差異清單。A、B 的模型不要在同一輪直接改主世界 `.blend`；核心組依預覽、幾何 QA 與 PWA 試走結果再做場景整合。成果欄標「製作者」與「整合者」，Git 提交須使用實際操作者身分；由 z1nnz 執行整合時才使用 z1nnz 提交身分。
