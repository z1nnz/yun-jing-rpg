# 工程邊界

## 服務

| 部分 | 責任 |
|---|---|
| Unity 客戶端 | 畫面、輸入、預測及結果呈現 |
| Unity 專用程序 | 區域移動、戰鬥與即時狀態裁定 |
| NestJS API | 帳號、角色、資產、生產、宗門與交易 |
| PostgreSQL | 正式持久資料與資產真相 |
| Redis | 快取、排隊與短期工作；不作最終資產依據 |

本機以 PGlite 跑相同 SQL。它方便測試，不代表外部 PostgreSQL 負載已通過。

## 資產一致性

- actor 只能來自認證，不能相信客戶端欄位。
- 每次資產操作帶 requestId；相同 requestId 重送回原結果。
- 扣除、增加、帳本和收據在同一交易完成。
- 資料庫失敗時停止發獎，不改用客戶端結果。
- `births` 保存先天，`players.state` 保存後天狀態。
- 正式 API 不提供指定出生、跳過十日或任意發獎端點。

## 認證

- 本機測試登入只在 local 模式與 loopback 開放。
- 正式流程使用系統瀏覽器、PKCE、短效 access token、可撤銷 refresh token及單次區域票證。
- 同一角色同時只有一個可寫入連線。
- 遊戲使用自己的 Firebase 專案；不複製樹伴憑證或資料。

## Unity 與內容

- Unity `6000.0.85f1`、URP `17.0.4`、FishNet `4.7.2` 固定版本。2026-10-25 起改用 6000.0.85f1。FishNet 4.7.4 的 Yak 外掛無法編譯，4.7.3 需要 Unity 6.3 以上的 `SceneHandle`，因此固定在 4.7.2。
- 大型素材使用 Git LFS；不得提交 `Library`、`Temp`、建置產物、憑證或私鑰。
- 道具、配方、功法及事件使用版本化資料定義。
- 新模型必須保留三視圖、來源、比例、面數、LOD、碰撞與匯出驗證。
