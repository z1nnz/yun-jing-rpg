# 青溪狩獵區：灰盒演示（替身演練）

日期：2026-10-25。在 Blender 灰盒上，用替身模型照 layout 的路線演一次「出發 → 看線索 → 發現兔群 → 兔子逃跑 → 追上 → 走替代回程 → 回到商販」，方便目視驗收配置。

**這是腳本排好的演練，不是遊戲實機，也不是 Unity 畫面。** 以下都沒有模擬：

- NavMesh、CharacterController
- 山兔 AI、戰鬥、掉落
- 出售 API 與連線

## 重建

```sh
blender --background --factory-startup --python-exit-code 1 --python docs/graybox/qingxi-hunt/blender/demo/build_hunt_demo.py -- --render follow,map
```

- **不加 `--render`：** 只產生 `.blend` 與 `demo_report.json`。
- **其他參數：** `--speedup` 是影片倍速，預設 2；`--fps` 預設 24。
- **讀取的檔案（都不會被修改）：**
  - `../../layout.json`
  - `packages/content/hunting.json`
  - `../QingxiHuntGraybox_blockout.blend`

## 內容

| 檔案 | 說明 |
| --- | --- |
| `demo_follow.mp4` | 跟拍玩家 1，距離 6 m、仰角 20°，1280 × 720，2 倍速。 |
| `demo_map.mp4` | 正上方地圖，人物與兔子加了彩色圓環，2 倍速。 |
| `QingxiHuntDemo.blend` | 可在 Blender 按空白鍵播放。畫面上的遊戲時間只在渲染時更新。 |
| `demo_report.json` | 時間軸、兔子逃跑路徑、兩人間距與鏡頭遮擋紀錄。 |

替身全部是「附加複製」，`art/incoming/dondon/` 的來源檔不變：

- 玩家 1：QPlayerMale v006；玩家 2：QPlayerFemale v006。兩者都用既有的待機／走路動作。
- 6 隻山兔：QMountainRabbit v002。它沒有骨架，所以用整體跳動代替動作。

## 演出規則

- **玩家：** 速度 4 m/s（layout），兩人沿主路與替代回程左右各偏 0.8 m 並行，與 `validate_layout.py` 的兩人軌跡相同。追兔與走回路線時，用 0.5 m 格網 A* 繞開 layout 的阻擋盒。
- **走路動作：** 播放倍率和 UE 端一樣，是速度 ÷ 0.6 m/s，上限 3.4，所以腳步看起來會滑。
- **山兔察覺：** 玩家進入 7 m 就逃，數值取自 `hunting.json`。
- **山兔逃跑：** 逃向離玩家最遠的同群逃跑點，速度 5 m/s。這是假設值，內容資料還沒有兔子速度。逃跑點都在 28 m 牽繩範圍內。
- **捕獲：** A01 被追上時倒地，2 秒後消失；只是示意。A02 等 4 秒後跳回出生點。B、C 群只在原地跳動，這次路線沒經過它們。

## 這次演練量到的結果（2 倍速影片，遊戲時間）

| 事件 | 時間 |
| --- | --- |
| 經過線索 T01（2026-10-25 移到主路節點後重錄） | 25.5 秒 |
| 經過線索 T02 | 30.2 秒 |
| 第一次看見山兔（A02，60 m 內無遮擋） | 63.7 秒 |
| A01 察覺並逃跑（25.5 m 到逃跑點 FA2） | 71.6 秒 |
| A02 察覺並逃跑（11.7 m 到 FA3），之後回家 | 74.3 秒 → 88.0 秒 |
| 追上 A01 | 79.4 秒 |
| 開始走替代回程 | 92.2 秒 |
| 回到材料商販 | 143.7 秒（捕獲後 64.3 秒） |

- **兩人間距：** 全程最近 1.0 m，兩個膠囊不重疊。
- **跟拍鏡頭：** 每 0.2 秒檢查一次，744 次都沒有被地面或阻擋盒擋住。這裡沒有模擬鏡頭碰撞，也不等於手機實測。
- **與離線預檢的差異：** 離線預檢量到 61.2 秒首次看見兔子；這裡是 63.7 秒，因為人物走在偏移 0.8 m 的路線上，而且只算 60 m 內的視線。

## 限制

- 人物和兔子不會被阻擋盒推開，路線由腳本保證，不代表 Unity 物理行為。
- 兔子只會直線逃到一個逃跑點，不會再次逃跑或繞圈；捕獲沒有戰鬥流程。
- 灰盒只有少量樹石，畫面空曠，不能拿來判斷美術完成後的遮擋與視線。
